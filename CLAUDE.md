## Project Overview

Shopzit is a multi-vendor e-commerce platform built on Laravel 8, using a custom package-based modular architecture. The platform supports multiple payment gateways (Stripe, PayPal, cryptocurrency), extensive third-party integrations (Shopify, Algolia, Zendesk), and features both traditional web views and React-based interactive components.

## Quick Start for Developers

**First-time setup:**
```bash
cp .env.example .env          # Configure database & API keys
composer install              # May need: composer update
php artisan key:generate
npm install
php artisan migrate
php artisan passport:install
npm run dev
```

**Key locations for common tasks:**
- **Add API endpoint:** `Packages/{Package}/Routes/api.php` + `Packages/{Package}/Src/Http/Controllers/V2/`
- **Add scheduled task:** `app/Console/Kernel.php` schedule() method
- **Modify product logic:** `Packages/Product/Src/` (WARNING: Product.php is 7400+ lines)
- **Add helper function:** `app/Http/helpers.php` (check existing first)
- **Configure integrations:** `.env` file + `config/` directory
- **Migrations:** `database/migrations/` (198 existing migrations)

**Understanding the architecture:**
- 20+ custom packages in `/Packages/` (not standard Laravel Modules)
- V1 and V2 APIs run simultaneously (gradual migration in progress)
- Repository pattern used throughout (see Architecture Overview below)
- Hybrid frontend: Blade templates + React components

## Architecture Overview

### Custom Package-Based Structure

The codebase uses a **custom modular architecture** with 20+ packages in `/Packages/`. This is NOT the standard Laravel Modules package (though `nwidart/laravel-modules` is installed, it's minimally used).

**Package Structure:**
```
Packages/{PackageName}/
├── Config/
│   ├── config.php          # Package configuration
│   └── constants.php       # Package constants
├── Routes/
│   └── api.php             # Package API routes
└── Src/
    ├── Contracts/          # Repository interfaces
    ├── Http/
    │   ├── Controllers/    # V1 controllers
    │   │   └── V2/         # V2 controllers (newer)
    │   └── Requests/       # Form requests
    ├── Models/             # Package-specific models
    ├── Providers/
    │   ├── {Package}ServiceProvider.php  # V1 provider
    │   └── V2/                           # V2 provider
    ├── Repositories/
    │   └── Eloquent/       # Repository implementations
    └── Services/           # Business logic layer
```

**Active Packages:**
- `Core` - Base functionality, checkout, categories
- `Product` - Product management
- `Order` - Order processing
- `Cart` - Shopping cart
- `Auth` - Authentication
- `Admin` - Admin panel
- `Store` - Vendor/store management
- `Discount` - Coupons and discounts
- `Distributors` - Wholesale/distributor features
- `Shipping` - Shipping calculations
- `Search` - Algolia integration
- `Import` - CSV/Shopify imports
- `Stripe` - Stripe payment integration
- `Review` - Product reviews
- `Notifications` - Notification system
- `Klavio` - Klaviyo email marketing
- `Dashboard`, `Home`, `Report`, `SocialLogin`

**Important:** Each package registers its own routes via its ServiceProvider. Routes are loaded from:
- Main routes: `routes/api.php`, `routes/web.php`
- Package routes: `Packages/{Package}/Routes/api.php`
- To find a route, check the package's Routes directory or use `php artisan route:list`

### Dual API Versioning (V1 & V2)

Both versions run **simultaneously** in production:

**V1 Structure:**
- Controllers: `Packages/{Package}/Src/Http/Controllers/`
- Routes: `/api/v1/{package}/...`
- Service Providers: `Packages/{Package}/Src/Providers/{Package}ServiceProvider.php`

**V2 Structure:**
- Controllers: `Packages/{Package}/Src/Http/Controllers/V2/`
- Routes: `/api/v2/{package}/...`
- Service Providers: `Packages/{Package}/Src/Providers/V2/{Package}ServiceProvider.php`
- Features: Enhanced with AI integration, granular permissions, improved checkout

**Important:** When modifying existing features, check if both V1 and V2 implementations exist. Changes may need to be applied to both versions.

### Repository Pattern

All packages follow the Repository Pattern:

```php
// Interface
Packages/{Package}/Src/Contracts/{Package}RepositoryInterface.php

// Implementation
Packages/{Package}/Src/Repositories/Eloquent/{Package}Repository.php

// Registration in ServiceProvider
$this->app->singleton(
    ProductRepositoryInterface::class,
    ProductRepository::class
);
```

**When creating new features:**
1. Define interface in `Contracts/`
2. Implement in `Repositories/Eloquent/`
3. Register binding in ServiceProvider
4. Inject interface (not implementation) in controllers/services

### Service Layer Pattern

Business logic lives in Service classes:

```php
Packages/{Package}/Src/Services/{Package}Service.php
```

**Controller → Service → Repository** flow:
- Controllers handle HTTP requests/responses
- Services contain business logic
- Repositories handle data access

### Authentication & Authorization

**Authentication:**
- **API routes:** Laravel Passport (OAuth2) - use `auth:api` middleware
- **Web routes:** Session-based - use `auth` middleware

**Authorization Middleware:**
- `checkRole:{role}` - Check user role (admin, seller, buyer, support)
- `permission:{permission}` - Check permission (V1 routes)
- `userPermission:{permission}` - Check user permission (V2 routes)
- `StoreAccess` - Verify store ownership
- `AdminAccess` - Admin-only routes

**Example:**
```php
Route::middleware(['auth:api', 'userPermission:manage-products-store'])
    ->post('/product/store', [ProductController::class, 'store']);
```

### Scheduled Commands (Cron Jobs)

**IMPORTANT:** Scheduled tasks are defined in `app/Console/Kernel.php` schedule() method (lines 48-62).

**Note:** There's a legacy configuration in `routes/console.php` with duplicate scheduled tasks. In Laravel 8, scheduled tasks belong ONLY in `app/Console/Kernel.php`, not in `routes/console.php`. The `routes/console.php` file should only contain Artisan command definitions. If you see Schedule:: calls in `routes/console.php`, they can be safely removed as they're duplicates.

**Current Scheduled Tasks:**
- `discounts:update-status` - Every minute
- `site:map` - Daily at midnight
- `recommended:generate` - Every 10 minutes
- `slides:set-activate` - Every 30 minutes
- `package:check-expired` - Daily
- `ai:reset-quota` - Monthly on 1st
- `send:low-stock-notifications` - Daily
- `distributor:license-expired` - Daily
- `products:algolia-syncing` - Every 30 minutes
- `algolia:batch-update` - Every minute (with withoutOverlapping)
- `orders:cleanup` - Weekly
- `facebook:regenerate-feed` - Every 30 minutes

**Server crontab entry required:**
```bash
* * * * * cd /path-to-project && php artisan schedule:run >> /dev/null 2>&1
```

## Common Development Patterns

### Adding a New API Endpoint

**For V2 endpoints (recommended):**

1. **Create Controller** (or add to existing):
```php
Packages/{Package}/Src/Http/Controllers/V2/{Feature}Controller.php
```

2. **Define Route** in `Packages/{Package}/Routes/api.php`:
```php
Route::prefix('api/v2')->group(function () {
    Route::prefix('{package}')->group(function () {
        Route::middleware(['auth:api', 'userPermission:{permission}'])->group(function () {
            Route::post('/endpoint', [FeatureController::class, 'method']);
        });
    });
});
```

3. **Create Form Request** (validation):
```php
Packages/{Package}/Src/Http/Requests/{Feature}Request.php
```

4. **Create/Update Service** (business logic):
```php
Packages/{Package}/Src/Services/{Feature}Service.php
```

5. **Create/Update Repository** (if needed):
```php
Packages/{Package}/Src/Repositories/Eloquent/{Feature}Repository.php
```

### Adding a New Scheduled Task

1. **Create Command:**
```bash
php artisan make:command CommandName
```

2. **Register in** `app/Console/Kernel.php`:
```php
protected $commands = [
    \App\Console\Commands\CommandName::class,
];
```

3. **Schedule in** `app/Console/Kernel.php` schedule() method:
```php
$schedule->command('command:name')->daily(); // or everyMinute(), hourly(), etc.
```

### Adding a New Model

1. **Create migration:**
```bash
php artisan make:migration create_table_name_table
```

2. **Create model:**
```bash
php artisan make:model ModelName
```

3. **Place in appropriate package** if package-specific:
```
Packages/{Package}/Src/Models/ModelName.php
```

4. **Update model namespace** if in package:
```php
namespace Packages\{Package}\Src\Models;
```

### Working with Algolia Search

**Make model searchable:**
```php
use Laravel\Scout\Searchable;

class Product extends Model {
    use Searchable;

    public function toSearchableArray() {
        return [
            'id' => $this->id,
            'name' => $this->title,
            // ... fields to index
        ];
    }
}
```

**Import to Algolia:**
```bash
php artisan scout:import "App\Models\Product"
```

**Custom Algolia engine configured in:**
`app/Providers/AppServiceProvider.php` (lines 27-29)

## Troubleshooting & Common Issues

### PHP Version Compatibility

**Supported Versions:** PHP 7.3 - 8.0 (as specified in composer.json)

**PHP 8.5+ Deprecation Warnings:**
If running on PHP 8.5+, you may see deprecation warnings:
- `PDO::MYSQL_ATTR_SSL_CA is deprecated` - Can be safely ignored (framework issue)
- Google API client parameter type warnings - Can be safely ignored (third-party library)
- Helper function parameter order warnings in `app/Http/helpers.php:847` - Non-critical

These warnings don't affect functionality but indicate the codebase targets older PHP versions.

### Composer Issues

**"Lock file is not up to date" Error:**
```bash
# Solution: Update the lock file
composer update --no-interaction
```

**Missing vendor/bin directory:**
Dependencies weren't fully installed. Run `composer install` or `composer update`.

**"Class Schedule not found" in routes/console.php:**
This is a known issue. The `routes/console.php` file incorrectly uses `Schedule::` without proper Laravel 8 syntax. See Scheduled Commands section above.

### PSR-4 Autoloading Warnings

When running `composer install/update`, you may see PSR-4 warnings like:
```
Class Packages\Product\Src\Models\CategoryProduct located in
./Packages/Product/Src/Models/ProductCategory.php does not comply
with psr-4 autoloading standard
```

**These are NOT critical errors** - they're warnings about file names not matching class names. The application will still function. Known issues:
- `CategoryProduct` class in `ProductCategory.php` file
- `category.php` files (lowercase) containing `Category` classes
- `OrderService.php` files containing `CartService` classes

These files are still loaded via manual includes and don't break functionality.

### Deprecated Packages

Composer will warn about abandoned packages:
- `klaviyo/php-sdk` - No suggested replacement (still works)
- `paypal/rest-api-sdk-php` - Suggest using `paypal/paypal-server-sdk` for new integrations

**Action:** Continue using these for now unless migrating to newer alternatives is a priority.

### Missing .env File

**Symptom:** "Mailgun API credentials are not set" error during composer install
**Solution:** Create `.env` from `.env.example` BEFORE running composer commands:
```bash
cp .env.example .env
```

### Database Connection Issues

**Ensure:**
1. Database exists (create it manually if needed)
2. `.env` has correct credentials: `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`
3. Database server is running

**Test connection:**
```bash
php artisan migrate:status
```

### Asset Compilation Issues

**"Module not found" errors:**
```bash
# Clear npm cache and reinstall
rm -rf node_modules package-lock.json
npm install
```

**Legacy Node polyfills warning:**
The `webpack.mix.js` includes legacy polyfills for Web3/crypto libraries. This is intentional.

### Search/Algolia Issues

**Products not appearing in search:**
1. Check `.env` has `ALGOLIA_APP_ID` and `ALGOLIA_SECRET`
2. Re-import products:
   ```bash
   php artisan scout:flush "App\Models\Product"
   php artisan scout:import "App\Models\Product"
   ```

### Permission Issues

**"This action is unauthorized" errors:**
- Check user has correct role assigned
- Check permission is registered in database
- V2 routes use `userPermission` middleware (granular)
- V1 routes use `permission` middleware (basic)

## Important Notes

### Security
- Never commit `.env` file
- Never expose API keys in code
- Use Form Requests for validation
- Sanitize user input (XSS prevention)
- Use parameterized queries (Eloquent handles this)

### Code Style
- Follow PSR-12 coding standards
- Use type hints where possible
- Document complex business logic
- Keep controllers thin (move logic to services)

### Database
- Always use migrations (never modify database directly)
- Use Eloquent relationships over manual joins when possible
- Index foreign keys and frequently queried columns
- **IMPORTANT:** The `Product` model (`Packages/Product/Src/Models/Product.php`) is 7400+ lines with extensive relationships, scopes, and accessors. When modifying:
  - Understand existing scopes before adding queries
  - Use eager loading for relationships (variations, images, categories, store, reviews)
  - Be cautious with mass updates (large table)
  - Check both V1 and V2 versions if they exist separately
- Review existing migrations (198 total) to understand schema evolution

### Performance
- Use eager loading to prevent N+1 queries:
  ```php
  Product::with(['variations', 'images', 'store'])->get();
  ```
- Cache expensive queries
- Queue long-running tasks
- Optimize Algolia index updates (batch operations)

### Package Development
- Each package should be self-contained
- Don't create cross-package dependencies (use Core package for shared functionality)
- Register service providers in `config/app.php`
- Use package config files for package-specific settings

### Helper Functions & Constants

**Global Helpers** (`app/Http/helpers.php` - 2000+ lines):
Extensive collection of helper functions automatically loaded via composer.json. Key categories:
- Product helpers: `getProductDetails()`, `getProductImages()`, `getProductVariations()`
- Order helpers: `getOrderStatus()`, `calculateOrderTotal()`, `getBuyerOrdersCount()`
- Store helpers: `getStoreDetails()`, `getVendorProducts()`, `checkStoreStatus()`
- User helpers: `getUserRole()`, `checkUserPermission()`, `getActiveStores()`
- Utility helpers: `formatPrice()`, `generateSlug()`, `uploadImage()`

**Note:** Some helpers have deprecated parameter declarations (PHP 8.5 warnings). These still work correctly.

**Application Constants** (`app/Constants.php`):
Global constants for order statuses, payment types, shipping methods, etc. Referenced throughout the application.

**Before creating new helpers:**
1. Check if similar functionality exists in `helpers.php`
2. Consider if it belongs in a Service class instead
3. Ensure it's truly global functionality

### Debugging
- Check `storage/logs/laravel.log` for errors
- Sentry tracks production errors
- Use `dd()` or `dump()` for debugging
- Enable query logging: `DB::enableQueryLog();`
